## Potato OS v0.7.3

### 1. Model health in the model picker

The chat model dropdown now tells you whether a model will actually run on this device:

- **Untested** (orange): downloaded here, but never loaded on this device
- **Fails** (red): loading was attempted and llama-server never became ready; hovering shows the last error
- Every entry shows the GGUF size in GB, e.g. `Nemotron-3.5-Bolt-E4B-Q4_K_M (6.18 GB)`

Health is recorded per model and survives restarts, so a model that failed keeps its red state until it actually loads.

### 2. Visible llama-server failures

When llama-server keeps crashing, the status card now shows the reason (exit code plus llama-server's last line) and a **Retry** button, instead of staying on "BOOTING" with no explanation.

### 3. Adaptive context size

llama-server's `--ctx-size` now comes from, in order: a manual override in advanced settings, `POTATO_CTX_SIZE`, or an automatic rule (8192 for models of 5 GiB or more on an 8 GB Pi 5), defaulting to 16384. On the Pi the KV cache at 8k is roughly half of what 16k used.

### 4. Fixes and platform changes

- Models deleted outside the app (for example with `rm` over SSH) no longer linger in the picker as "not downloaded".
- The sidebar Platform block shows the llama runtime in use (`ik_llama` or `llama_cpp` plus its commit).
- The CPU governor is pinned to `performance` while the Potato service runs and restored to `ondemand` when it stops.
